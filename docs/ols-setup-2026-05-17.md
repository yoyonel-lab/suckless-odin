# OLS (Odin Language Server) — Installation & Configuration

**Date**: 2026-05-17  
**Status**: Fonctionnel (Go to Definition, Hover, Completion, References)

## Prérequis

- VS Code avec l'extension **Odin Language** (`danielgavin.ols`)
- Odin compiler installé (ici : `dev-2026-05-nightly`)
- Linux x86_64

## Architecture

```
~/.local/bin/
├── ols          ← Binaire OLS (language server)
├── odinfmt      ← Formatteur Odin
├── odin → /tmp/odin-linux-amd64-nightly+2026-05-03/odin  (symlink)
└── builtin/
    ├── builtin.odin
    └── intrinsics.odin

<project>/
└── ols.json     ← Configuration par projet (collections, checker, etc.)
```

**Points critiques** :
1. Le dossier `builtin/` **DOIT** être à côté du binaire `ols`
2. `odin` **DOIT** être dans le PATH accessible par `sh` (VS Code lance OLS qui exécute `odin check` via shell)
3. `ols.json` **DOIT** être à la racine du workspace

## Installation pas à pas

### 1. Télécharger OLS précompilé

```bash
# Trouver la dernière release
curl -s https://api.github.com/repos/DanielGavin/ols/releases/latest \
  | grep "browser_download_url.*x86_64-unknown-linux-gnu" \
  | cut -d '"' -f 4

# Télécharger (adapter l'URL selon la release)
cd /tmp
curl -sL "https://github.com/DanielGavin/ols/releases/download/dev-2026-05/ols-x86_64-unknown-linux-gnu.zip" \
  -o ols.zip
unzip -o ols.zip -d ols-extract
```

### 2. Installer en scope utilisateur (~/.local/bin)

```bash
mkdir -p ~/.local/bin/builtin

cp ols-extract/ols-x86_64-unknown-linux-gnu ~/.local/bin/ols
cp ols-extract/odinfmt-x86_64-unknown-linux-gnu ~/.local/bin/odinfmt
cp ols-extract/builtin/* ~/.local/bin/builtin/

chmod +x ~/.local/bin/ols ~/.local/bin/odinfmt
```

### 3. Rendre `odin` accessible dans le PATH

OLS exécute `odin check` via `sh`. Si `odin` n'est pas dans un répertoire standard du PATH, créer un symlink :

```bash
ln -sf /chemin/vers/odin ~/.local/bin/odin

# Vérifier
which odin
odin version
```

> **Note** : `~/.local/bin` doit être dans votre `$PATH`. Vérifier avec `echo $PATH | tr ':' '\n' | grep local`.
> Si absent, ajouter dans `~/.bashrc` ou `~/.profile` : `export PATH="$HOME/.local/bin:$PATH"`

### 4. Extension VS Code

Installer depuis le marketplace :
- ID : `danielgavin.ols`
- Nom : "Odin Language"

Paramètres optionnels de l'extension (Settings UI ou `settings.json`) :

```jsonc
{
  // Chemin explicite vers OLS (optionnel si déjà dans PATH)
  "ols.server.path": "/home/USER/.local/bin/ols"
}
```

### 5. Créer `ols.json` à la racine du projet

```jsonc
{
  "$schema": "https://raw.githubusercontent.com/DanielGavin/ols/master/misc/ols.schema.json",
  "enable_semantic_tokens": true,
  "enable_document_symbols": true,
  "enable_hover": true,
  "enable_snippets": true,
  "enable_format": true,
  "enable_references": true,
  "enable_inlay_hints_params": true,
  "enable_procedure_snippet": true,
  "odin_command": "/chemin/vers/odin",
  "odin_root_override": "/chemin/vers/odin-root",
  "checker_args": "-vet -strict-style",
  "verbose": false,
  "profile": "default",
  "profiles": [
    {
      "name": "default",
      "os": "linux",
      "checker_path": ["src"],
      "defines": {}
    }
  ],
  "collections": [
    { "name": "deps", "path": "deps" }
  ]
}
```

**Champs importants** :

| Champ | Rôle |
|-------|------|
| `odin_command` | Chemin absolu vers l'exécutable `odin` |
| `odin_root_override` | Dossier racine Odin (contient `core/`, `vendor/`, `base/`) — nécessaire pour résoudre les imports standard |
| `checker_path` | Package(s) à vérifier (ex: `["src"]`) |
| `collections` | Collections custom du projet (ex: `deps/odin-imgui`) |
| `profiles` | Permet de définir OS/arch/defines différents |

### 6. Redémarrer OLS

Commande palette VS Code : **OLS: Restart Server** (`ols.restart`)

## Dépannage

### `sh: 1: odin: not found`

OLS lance `odin check` via `/bin/sh`. Solution : symlink `odin` dans `~/.local/bin/` (ou tout répertoire dans le PATH de `sh`).

### `No definition found for 'xxx'` (fonction core/vendor)

Vérifier `odin_root_override` dans `ols.json` — doit pointer vers le dossier contenant `core/` et `vendor/`.

```bash
ls $(jq -r .odin_root_override ols.json)/core/strings/
# Doit lister des .odin
```

### `ENOENT` au lancement

L'extension tente de lancer un binaire inexistant. Vérifier le setting `ols.server.path` dans VS Code ou s'assurer que `ols` est dans le PATH.

### `-32603 InternalError` sur toutes les requêtes

OLS a démarré mais crash à l'indexation. Causes possibles :
- `builtin/` absent à côté du binaire `ols`
- `odin_root_override` incorrect
- Fichier `.odin` avec erreur de syntaxe bloquante

Activer `"verbose": true` dans `ols.json` et consulter Output > Odin Language.

### OLS bloque le terminal

**Ne jamais lancer `ols` directement** — c'est un serveur LSP qui attend du JSON-RPC sur stdin. Il n'a pas de `--version` ni de mode CLI. Seul VS Code (ou un éditeur LSP) doit le lancer.

## Mise à jour

```bash
# Mettre à jour OLS (même procédure que l'installation)
pkill -f "ols"  # Tuer l'instance en cours
# Télécharger nouveau zip, extraire, copier dans ~/.local/bin/
# Redémarrer VS Code ou ols.restart
```
